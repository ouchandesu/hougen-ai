# 実装と検証（ステップ 5〜6）

## 検証ゲート

このレポジトリにはビルド・lint・型チェック・フォーマッタが**無い**（npm 依存ゼロ、ADR 0002）。
代わりに持っているのは次の表だけ。無いものを「通った」と書かない。

| 対象 | コマンド |
| --- | --- |
| format / lint | 無い |
| 型 | 無い |
| 構文（編集直後） | フックが自動で走る（`.claude/hooks/check-syntax.js`）。`api/*.js` は `node --check`、HTML はインライン `<script>` を構文解析 |
| 検査テスト | 段階 4 で追加 |
| コミット件名 | 日本語で 1 行（検査なし） |
| スキーマ変更後 | 手元で検査できない。適用する SQL を PR に貼り、人間が Supabase で適用 |
| ビルド | 無い（Vercel が `api/` をそのまま関数にする） |

## 自分のせいでない赤も直す

検証で見つけた赤は、自分の変更と無関係でもここで直して同じ PR に入れる。
放置された赤は次の人の罠で、他に見ている人はいない。**誰の赤だったか（どのコミット由来か）を PR に書く。**

## テストを足したら、実行対象に入っているか確かめる

実行対象の指定から漏れたテストは、緑のまま何も測らない。足したあと、実行出力にそのテスト名が出ているのを見る。

## 手元で動かせないもの

Anthropic API / Supabase を呼ぶ経路は、鍵が無ければ手元で通しで動かせない。
経路をスタブで確かめた場合は「スタブで確認」と書き、実サービスで動いたとは書かない（autonomy-and-checkpoints.md）。
