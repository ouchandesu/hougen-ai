# 0003: 対象方言を1つに絞りapi/_dialect.jsに定義を集める

- ステータス: Accepted
- 実装状況: 一部実装（API 側は api/_dialect.js に集約済み。index.html の表記は未対応 — 台帳 FE-417）
- 決定: 扱う方言は 1 つ（現在は愛媛県の伊予弁）とし、プロンプトに入る方言名・地域名・語尾・対象地域で言わない言い回し・古い表現は api/_dialect.js の TARGET_REGION と共通ルール関数から組み立てる。無理に方言へ寄せず、他地域と共通の言葉は対象地域で日常的に使うものに限り控えめに認める

## コンテキスト

以前は地域を選んで複数の方言を扱っていた（git 履歴）。
方言の生成・解説をモデルに任せると、近い地域の方言（関西弁など）の語尾や言い回しが混ざりやすい。
一方で、無理に方言へ寄せる指示では、今は使われない表現や実在しない言い回しが出て、文章が不自然になった。
関西弁などと共通の言葉（例: 「いかん」）には、対象地域でも日常的に使うものがあり、一律に禁じると自然な伊予弁まで削れる。
これらの指示は、調べる・変換・研修のすべてのプロンプトに同じ文面で入れる必要がある。

## 決定

1. 利用者が地域を選ぶ UI は持たない。対象は 1 つに固定する。
2. 対象の都道府県名・方言名・特有の語尾・対象地域の話者が普段言わない他地域特有の言い回し・今は使われない古い表現は、`TARGET_REGION` の 1 か所に置く。
3. 全プロンプト共通の指示は、`api/_dialect.js` の関数から差し込む。共通の指示は、純度管理と確かさ・出力形式、変換系のみ自然さの優先と方言の濃さ。
   各 `api/*.js` のプロンプトに、方言名や地域名を直書きしない。
4. 変換では自然さを最優先にする。方言の濃さは変えてよい範囲の上限であり、自然な置き換えが無ければ原文のままでよい。
5. 他地域と共通の言葉は、対象地域で日常的に使い違和感のないものに限り使ってよいが、目立つほど入れない。
   確信の持てない表現は、使わず・出題せず・解説で断定しない。

## 帰結

- 別の方言へ切り替えるときに、API 側は `TARGET_REGION` の値を差し替えるだけで済む。
- フロント（`index.html`）の見出し・バッジ・API に送る `region` の値は、まだ直書きで `TARGET_REGION` を反映しない。
  切り替えるとフロントとプロンプトの表記が食い違う。
- 複数の方言を同時に扱う要望には応えられない。
- 「日常的に使うか」「入れすぎか」の線引きはモデルの判断に任せるため、出力はぶれる。確かな線引きは ADR 0004 の監修済み辞書で持つ。
- 自然さを優先するので、方言の濃さを変えても結果が変わらない入力がある。

## 却下案

- 地域選択を残して複数方言を扱う: 方言ごとの混入防止の指示を保てず、出力に他地域の方言が混ざる。
- 他地域の方言を一律に禁じる: 対象地域でも日常的に使う共通の言葉まで削れ、かえって不自然になる。
