# 0004: 監修者が確認した辞書を方言内容の正とする

- ステータス: Accepted
- 実装状況: 未実装（現状は全内容を毎回モデルが生成している — api/lookup.js, api/quiz.js, api/convert.js）
- 決定: 方言の語・例文・意味・アクセント・使用頻度・用例は監修者が確認した辞書に持ち、モデルの生成物は未監修として区別する。辞書には放送素材の用例を番組名・放送日つきで保存する

## コンテキスト

調べる・研修・変換の内容は、すべてその場でモデルが生成している。利用者は放送局で、読み聞かせやアクセント指導のように局の名前で外に出す使い方が要望にある。
モデルは、使用頻度（よく使う／マイナー）・アクセント・時系列の変化について根拠を持たない。
監修者（伊予弁の話者であるプロジェクトの開発者本人）が確認できる体制がある。
放送局からは、番組の映像・切り抜きを用例として保存してよいと了承を得ている。

## 決定

1. 方言の内容の正は辞書とする。辞書の各項目は、監修者が確認したかどうかの状態を持つ。
   確認済みの項目だけを「監修済み」として表示し、使用頻度とアクセントは確認済みの項目にだけ出す。
2. モデルは辞書を土台に使う（出題・解説・変換の根拠として辞書の項目を渡す）。
   辞書に無い内容を生成したときは、未監修として画面上で区別する。
3. 用例には出典（番組名・放送日・放送素材）を持たせる。時系列の分析は、この放送日から行う。
4. 辞書は Supabase に置く。スキーマは他のテーブルと同じくリポジトリの外で管理し、変更は SQL を人間が適用する。

## 帰結

- 監修者は 1 名なので、確認待ちの項目が溜まると、監修済みの内容はそのペースでしか増えない。
  入力（テロップ担当などの人手や、モデルによる下書き）と確認を分け、確認する画面を作る必要がある。
- 使用頻度・アクセントの表示と、アクセントの自動判定（ADR 0005 の音声にも使う）は、この辞書ができるまで作れない。
- 放送素材そのものの保存先（Supabase Storage か、別のストレージか）と容量・費用は未決。月額予算の相談が済むまで、用例はまず文字起こしと出典情報で持つ。
- 辞書と生成物の二本立てになるため、`api/*.js` のプロンプトに辞書の項目を差し込む経路と、応答に「監修済みか」を載せる JSON 契約の変更が要る。

## 却下案

- モデル生成のまま注意書きを付ける: 頻度・アクセント・時系列に根拠が無く、放送局の名前で出せない。
