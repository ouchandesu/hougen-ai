# ADR（設計判断の記録）

索引は `index.md`（生成物。手で書かない）。

## 運用ルール

- **1 ファイル = 1 決定。** ファイル名は `NNNN-タイトル.md`。本文 1 行目の `# NNNN:` はファイル名の番号と必ず一致させる。
- **本文は常に現行の決定だけを書く。** 決定が変わったら本文を書き換える。
  追記・訂正・改訂記録・取り消し線で経緯を残さない。覆された側の記述は消す（履歴は git が持つ）。
- **新しい ADR を立てるのは決定の主題が変わるときだけ。** 同じ主題の訂正・具体化・適用先の拡張は元 ADR を書き換える。
- **外から引くときは素の綴り（`ADR 0001 決定 2`）だけを書く。リンクにしない。**
  相対リンクは引く側の深さに依存し、ADR を移した日に黙って切れる。番号は振り直さない識別子なので綴りで引ける。
  ADR 同士の相互リンクだけは例外。
- ステータス: `Proposed` → `Accepted` → （`Deprecated` | `Superseded by NNNN`）
- 各 ADR は「コンテキスト / 決定 / 帰結（トレードオフ含む）」を必ず含む。
- **ADR に書かないもの**: テスト観点（テストが持つ）、コードや SQL の全文（コードが持つ）、
  検証ログや PR 番号（git が持つ）、ベンダの制限表（向こうの都合で変わる）、UI の仕様。
  却下案は「案の名前 + 負けた理由 1 つ」の 1 行。
- **ステータス（決定の状態）と実装状況（ツリーの状態）を 1 列にまとめない。**
  実装状況はヘッダの `- 実装状況:` に置き、**根拠のファイルパスを必ず添える**。

## ヘッダの形

索引はこの 3 行から生成する。

```
# NNNN: タイトル

- ステータス: Accepted
- 実装状況: 実装済み（api/_auth.js）
- 決定: 1 行の要約
```

## 番号と並び

並行して ADR を書くブランチが無い前提で、番号は最大値 + 1、索引は番号順にしている。
複数のブランチやエージェントが同時に ADR を足すようになったら、番号を未使用からランダムに引き、
索引を題の文字順にする（同じ行位置での衝突を避けるため）。

## 道具

- `npm run adr:new -- "タイトル"` — `template.md` から次の番号で 1 本作り、索引を再生成する
- `npm run adr:index` — 各 ADR のヘッダから `index.md` を再生成する（差分は `npm test` が落とす）

## やらなかったことの台帳

`未対応実装/` — 決定は済んでいるが実装・検証が未了のもの。設計が未決のもの（= ADR 候補）は入れない。
