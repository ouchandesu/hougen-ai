# やらなかったことの台帳

**決定は済んでいるが、実装・検証が未了のもの**の一覧。設計が決まっていないもの（= ADR 候補）は入れない。

## 運用ルール

- ドメインごとに 1 ファイルで、ファイルごとに ID 接頭辞を持つ。
  - `フロントエンド.md`（`FE-`） / `API.md`（`API-`） / `データベース.md`（`DB-`）
- 種別は行の列で表す: `阻害` / `未実装` / `未検証` / `負債`
- ID の番号は 100〜999 からランダムに引く。**振り直さない・空き番号を再利用しない**（コードコメントや ADR が ID を引く）。
- **done になった行は消す。** チェックを付けて残さない。消したあと、その ID をレポジトリ全体で検索して参照を直す。
- 各行は**実在するファイルパス**を引く。台帳は腐るので、読み手が現物を確かめられるようにする
  （パスの実在は `scripts/checks/references.test.js` が見る）。

## 行の形

```
| ID | 種別 | 内容 | 根拠 |
| --- | --- | --- | --- |
| FE-123 | 負債 | 1 行で | `index.html` |
```
