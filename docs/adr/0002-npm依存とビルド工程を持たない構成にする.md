# 0002: npm依存とビルド工程を持たない構成にする

- ステータス: Accepted
- 実装状況: 実装済み（package.json, index.html, admin.html, api/）
- 決定: フロントは単一 HTML、サーバーは api/ の CommonJS 関数とし、npm 依存とビルド工程を持たず、外部サービスは fetch で呼ぶ

## コンテキスト

画面は 2 枚（利用者向けと管理者向け）、サーバー処理は Anthropic API と Supabase への中継だけで、規模が小さい。
Vercel は `api/` 配下の関数と静的ファイルをビルド無しでそのまま配信できる。

## 決定

1. フロントは `index.html` と `admin.html` の 2 ファイルで、HTML・CSS・JS をそれぞれ 1 ファイルに持つ。
2. サーバー処理は `api/*.js`（CommonJS、Node 18 以上の組み込み `fetch`）。共有処理は `_` 始まりのファイルに置く。
3. `package.json` に `dependencies` を持たない。Anthropic API と Supabase の REST / Auth はサーバー側から fetch で呼ぶ。
4. 例外として、ブラウザ側の Supabase クライアントだけは CDN（jsDelivr）の UMD 版を `<script>` で読む。
5. 開発用の道具（検査テスト、ADR の道具、フック）も Node の組み込み機能だけで書く（`node --test` など）。

## 帰結

- ビルド・lint・型チェックが無いので、構文エラーや名前の打ち間違いはブラウザや関数の実行時まで表に出ない。
  編集直後の構文検査をフックで補っている（`.claude/hooks/check-syntax.js`）。
- 同じ値の写し（モデル ID、方言の表記、利用ログの action 名）がファイルをまたいで散りやすい。
  壊れても何も落ちない写しには検査テストを置く（`scripts/checks/`）。
- `index.html` は 1 ファイルで大きく、差分が同じファイルに集中する。
- CDN の supabase-js はメジャー版だけの指定なので、マイナー版の更新が黙って入る。

## 却下案

- フレームワーク（Next.js など）とバンドラ: この規模に対してビルド工程と依存の更新作業が見合わない。
